# Contributing to Pixel Candy Glass

1. Read relevant product and engineering specifications.
2. Inspect existing implementation and recent history.
3. For behavior changes, propose a plan and obtain owner approval.
4. Keep changes small and reviewable.
5. Do not remove or replace existing functionality without explicit approval.
6. Do not invent unresolved product rules.
7. Add tests and update docs with behavior changes.
8. Keep secrets/private data out of Git.
9. Use descriptive commits and reference issue IDs.
10. Verify acceptance criteria, regressions and limitations before calling work complete.

For major milestones request independent review. Only one agent should edit a given working tree at a time; parallel agents should use read-only analysis or isolated branches/worktrees.
