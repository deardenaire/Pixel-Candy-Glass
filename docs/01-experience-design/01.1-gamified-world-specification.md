# 01.1 — Gamified World Specification

**Status:** To be authored in detail after the owner uploads actual world/reference images. **Priority:** Next major experience-design deliverable. This outline is not an approved final mechanic design.

## Purpose
Specify the world as a persistent, interactive experience. A developer and artist unfamiliar with prior conversations must implement it without guessing. Every system needs behavior, state, edge cases and acceptance criteria—not appearance-only descriptions.

## Required chapters
1. World identity, emotional target, tone, atmosphere and boundaries.
2. Composition/layer stack: sky, distant scenery, midground, foreground, ground/platforms, characters, props, lighting and UI overlays; ordering, depth and parallax.
3. Scene model: types, selection, transitions, unlocks, customization, persistence and restoration.
4. Environment behavior: clouds, wind, light, weather, water, vegetation, ambient movement, time-of-day and reduced-motion behavior.
5. Companion system: roster, placement, sprite scale, idle states, expressions, reactions, interaction vocabulary, personality and accessibility.
6. Companion progression: attributes, friendship/status and unlocks. Do not invent formulas or currencies before approval.
7. Interactive objects: tappable props, collectibles, destinations and contextual actions; hit areas, feedback, cooldowns and persistence.
8. Gamification: XP, levels, achievements, rewards and unlocks; authoritative events and duplicate prevention.
9. Productivity connections: tasks, habits, focus sessions, calendar and other approved activities affecting the world.
10. World interface: indicators, companion information, scene controls, inventory and contextual actions; always-visible versus expandable.
11. Mobile interactions: tap, swipe, drag, long-press, scrolling, touch targets, gesture conflicts and back behavior.
12. Persistence: scene, companion state, inventory, progression, preferences and recovery after refresh/offline/restart.
13. Art direction: pixel grid, logical resolution, sprite scale, palette, outline, shading, texture and compositing.
14. Animation: frame standards, loops, transitions, interruption, priority and reduced motion.
15. Edge states: first launch, locked scene, empty inventory, unavailable companion, offline, loading, failed save, missing/corrupt asset.
16. Performance: loading, caching, sprite rendering, animation budget, memory and device adaptation.
17. Acceptance criteria for every launch-critical system.

## Required interaction contract
For every interactive/reactive feature specify unique ID, purpose, entry point, preconditions, trigger, immediate feedback, state/data change, persistence/sync, repeated-input behavior, interruption/navigation, error recovery, accessibility/reduced-motion behavior and acceptance tests.

### Illustrative example only — not an approved mechanic
A task completion event could trigger a companion reaction. The contract must specify that the event is accepted only after the task save succeeds, a stable event ID prevents duplicate rewards, the animation has defined interruption behavior, and durable reward state survives reload. The actual animation and reward formula require owner approval.

## Required diagrams
World layer stack; scene/state transition map; companion state machine; productivity-event-to-world-reaction matrix; interaction inventory; asset dependencies; persistence/state ownership map.

## Open decisions
Exact reference interpretation; launch scene count/types; navigable world versus living home scene; companion roster/behavior; interaction density; progression economy; audio; customization boundaries.

## Completion gate
Do not mark approved until references have been reviewed, open decisions are resolved or explicitly deferred, and launch-critical behavior has acceptance criteria.
