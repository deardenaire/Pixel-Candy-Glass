# 01.3 — Application Screen & Interaction Specifications

**Status:** Framework document; final app inventory requires owner confirmation and code audit.

## Per-application specification
Create one file per approved app using the app-spec template. Define purpose, responsibilities, entry/world integration, navigation, every screen/subscreen, hierarchy, actions, forms/validation, search/filter/sort, edit/archive/delete, empty/loading/offline/error/success states, data ownership/persistence, cross-app events, reminders, Candy Glass treatment, pixel-art boundaries, mobile gestures, accessibility, performance, privacy and acceptance criteria.

## Candidate app areas — not a final launcher list
Primary to-do/calendar; Diary; Notes; Projects; Tools/personal resource library; Companions/World; Store/Rewards; Profile/Progress; Settings. Focus may be integrated rather than a separate launcher icon.

Reconcile the final structure against existing Mochi source and owner decisions. Avoid duplicate disconnected data.

## Cross-app contracts
Calendar schedules ↔ tasks/time blocks; task completion ↔ world reactions/reward ledger; habits ↔ calendar/streak history; focus sessions ↔ task time tracking/analytics; projects ↔ tasks/notes/files; diary ↔ optional date/event links. Define data owner, permissions, triggers, duplicate prevention, archive/delete effects and offline conflicts.

Do not generate specs from historical app names alone. Confirm final inventory first.
