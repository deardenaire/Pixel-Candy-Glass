# 01.2 — Pixel Art & Asset Production Bible

**Status:** Pending owner reference images and existing artwork.

## Purpose and boundary
Define consistent production rules for pixel-art environments, characters, companions, props and collectibles. Pixel art is not a universal filter for the application. Candy Glass remains the visual system for mobile shell and productivity UI.

## Reference analysis
For each reference record filename, source, intended use, relevant traits (composition, palette, pixel density, perspective, mood, animation), what to preserve, what not to copy, inspiration versus direct asset use, and provenance/rights. Do not infer pixel dimensions from images not yet inspected.

## Standards to decide from evidence
Logical canvas size; pixel grid; sprite dimensions/scale; alignment grid; camera/perspective and horizon; palette roles/limits; outline conventions; light direction; shading clusters; dithering/texture; parallax depth; transparency; animation frame dimensions and timing metadata.

## Asset families
World backgrounds/layers; terrain/platforms/tiles; companions and character sprites; expressions/reactions; props and interactive objects; collectibles/reward icons; scene decorations/seasonal variants; deliberately pixel-art UI-adjacent art; optional audio if approved.

## Production pipeline
1. Capture reference and write asset brief.
2. Specify use, dimensions, palette, perspective and state.
3. Create or commission artwork.
4. Export editable master and runtime formats.
5. Validate transparency, crisp edges, alignment and scale.
6. Test on target mobile sizes/backgrounds.
7. Optimize size/loading.
8. Record asset ID, version, provenance, license and dependencies.
9. Commit in a meaningful batch.

## Rendering and optimization
Use image/sprite assets for artwork; CSS/code for layout and behavior. Use nearest-neighbor scaling where needed. Avoid blur/resampling artifacts. Use atlases/sprite sheets where appropriate. Load only active-scene assets when possible; reuse/cache assets; avoid unnecessary simultaneous animation; provide missing-asset fallbacks. Compression must preserve pixel appearance.

## Naming
Suggested: category_subject_variant_state_vNN.ext. Examples: environment_meadow_day_base_v01.png; companion_mochi_idle_front_v01.png; prop_mailbox_closed_v01.png. Maintain stable asset IDs even if filenames change.

## Asset register
Record ID, filename, category, scene/app, dimensions, frame count, format, transparency, master/runtime files, provenance/license, status (planned/received/review/approved/integrated/deprecated), spec reference, dependencies and notes.

## Quality gate
Reject inconsistent perspective, palette, pixel density, outline, light direction, blur, stray pixels, incorrect transparency, weak focal hierarchy or unlicensed provenance.

## Open decisions
Reference-specific pixel dimensions, sprite scale, palette, tile size, camera and export formats remain open until owner material is reviewed.
