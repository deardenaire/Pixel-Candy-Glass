# 00.3 — Mobile Experience Specification

**Status:** Starter summary; reconcile with the owner's authored document.

## Platform priority
Mobile-first, not mobile-only. Desktop adaptation may follow as a separately validated experience. Do not shrink a desktop interface and call it mobile design.

## Shell flow
1. Lock screen and date/time.
2. PIN/unlock flow, with security model decided separately.
3. Home screen and app icons.
4. App launching and navigation.
5. Shared settings and system feedback.

The shell should feel like a coherent personal device environment, not a website inside a phone mockup.

## Touch and navigation
Comfortable touch targets; no essential hover-only actions; clear tap/swipe/scroll/long-press behavior; predictable back navigation; safe-area, keyboard and viewport handling; prevent accidental destructive actions; preserve useful editing and scroll state.

## Responsive targets
Specify small, typical and large phones. Tablet support must be explicit. Desktop is a later, separately approved scope. Recompose hierarchy for narrow screens rather than scaling desktop UI.

## Accessibility and resilience
Readable contrast/type; screen-reader labels; keyboard focus where applicable; reduced motion; clear empty/error states; no color-only meaning; documented offline and interrupted-session behavior.

Every screen spec needs viewport targets, interaction criteria, persistence expectations, loading/empty/error states and visual evidence.
