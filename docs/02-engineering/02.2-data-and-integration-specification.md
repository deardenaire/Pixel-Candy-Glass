# 02.2 — Data & Integration Specification

**Status:** Pending audit and final app inventory.

## Purpose
Define data ownership and cross-app behavior so tasks, events, habits, focus sessions, projects and world progress do not become conflicting disconnected records.

## Required artifacts
Entity relationship diagram; data dictionary; source-of-truth matrix; event catalogue; sync/conflict rules; archive/delete/restore semantics; migration plan; backup/export format.

## Candidate domains
Only include approved domains: profile/preferences; calendar events; tasks/subtasks/time blocks; habit definitions/history; focus sessions/tracked time; projects and linked tasks; notes/diary; companions/world state/inventory; XP/achievements/reward ledger; asset metadata/customizations.

For every entity define stable ID, owner, fields, validation, timestamps, deletion/archive semantics and migration behavior. For every event define producer, consumer, unique ID, payload, idempotency, ordering, retry and offline behavior. A retried task-completion event must not grant duplicate rewards. Never display permanent success before durable save succeeds.

Storage, sync, account model, backup, encryption and offline-first scope remain open until audit and owner review.
