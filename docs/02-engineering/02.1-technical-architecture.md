# 02.1 — Technical Architecture

**Status:** Pending read-only audit. Do not fill with guessed technologies.

Record current architecture, framework/language/version, build/development/deployment commands, routing, component structure, state management, persistence/schema/migrations, authentication/PIN/session model, asset pipeline, sprite rendering, animation, offline/sync, external APIs, secrets handling, errors/logging, accessibility, responsive behavior, tests, hosting, backups, restore and rollback.

## Principles
Prefer smallest safe changes to existing system. Do not select a new framework without evidence. Separate durable domain data from transient UI state. Avoid duplicated sources of truth. Keep business rules testable. Treat migrations/data deletion as high risk; require backup, tested restore and owner approval.

Record major decisions with context, options, decision, consequences, risks and owner approval using the decision template.
