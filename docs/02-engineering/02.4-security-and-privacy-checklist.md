# 02.4 — Security & Privacy Checklist

- [ ] Identify data collected and why; minimize collection.
- [ ] Define account/session boundaries and authorization.
- [ ] Do not treat a client-side PIN screen as strong authentication by itself.
- [ ] Never store plaintext PINs, passwords, tokens or API secrets in source.
- [ ] Choose credential storage/hashing for the real platform and threat model.
- [ ] Keep secrets out of Git history, logs, screenshots and fixtures.
- [ ] Validate and sanitize untrusted input.
- [ ] Protect data in transit and at rest where applicable.
- [ ] Define export, backup, restore and deletion behavior.
- [ ] Review dependencies and vulnerabilities.
- [ ] Avoid committing private user files or unrelated personal records.
- [ ] Test authorization/data isolation if accounts or cloud storage exist.
- [ ] Document third-party services and data handling.

A decorative PIN keypad is not a security feature. Implementation must match actual security requirements.
