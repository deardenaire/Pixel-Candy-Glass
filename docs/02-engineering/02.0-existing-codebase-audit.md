# 02.0 — Existing Codebase Audit

**Status:** Not started. **Mode:** Read-only until owner approves a change plan.

## Mission
Inspect existing source, documentation, assets and application behavior before proposing architecture changes. The project grows from Mochi Calendar / Mochi Workspace; preservation is a priority.

## Restrictions
- Do not edit, delete, rename, reformat or move files during audit.
- Do not install dependencies or run destructive migrations.
- Do not replace framework or assume a rewrite is needed.
- Do not claim a feature works based only on component names or source appearance.
- Do not remove apps because responsibilities appear duplicated; map first.
- Use a safe local copy for execution and document commands.

## Required report
1. Repository/file inventory.
2. Framework, language, package manager, versions, entry points and build commands.
3. Feature inventory: behavior, source location, data read/write, dependencies, status (verified/partial/broken/placeholder/unknown), evidence and risks.
4. Preservation map: functionality, data, visual systems, assets and interactions to protect.
5. Architecture: routing, state, persistence, schemas, integrations, auth/PIN, assets, responsive behavior and performance.
6. Mobile readiness: safe areas, touch, keyboard, navigation, installability, offline and device performance.
7. Ranked risks and smallest safe recommendations.
8. Contradictions and owner questions.
9. Implementation sequence grounded in findings.

## Acceptance criteria
No source changes occurred; major features are accounted for; claims cite paths and test evidence; unknowns are explicit; preservation risks are visible; facts are separated from recommendations.
