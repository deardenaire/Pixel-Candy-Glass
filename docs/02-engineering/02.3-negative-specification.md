# 02.3 — Negative Specification: Prohibited Regressions

| Do not | Required alternative |
|---|---|
| Delete or silently remove existing app/capability | Inventory, map overlap, propose migration and obtain owner approval |
| Replace working behavior with placeholder | Preserve and implement approved workflow end-to-end |
| Rewrite without evidence | Audit first; recommend smallest safe change |
| Flatten Candy Glass into generic pastel SaaS | Follow approved material, lighting, typography and composition |
| Apply pixel art to every UI surface | Keep pixel art in world/art layer and Candy Glass in productivity UI |
| Replace custom art with generic icons | Reuse approved art or submit asset request |
| Add nonfunctional controls | Implement and test every visible action |
| Create duplicate disconnected data | Define one source of truth and cross-app contracts |
| Invent progression/app/companion rules | Mark open decisions and ask owner |
| Hide incomplete behavior behind animation | Complete behavior and show honest feedback |
| Change approved design casually | Submit a change proposal |
| Perform destructive migrations without backup | Plan, back up, test restore and obtain approval |
| Mark work verified without evidence | Attach reproducible tests/screenshots/logs/recordings |
| Commit secrets or private data | Use secure secret management and sanitized fixtures |
| Reduce visual quality to mask performance issues | Profile and optimize while preserving art direction |

Any removal, rename, relocation or material behavior change must document current behavior/evidence, rationale, user/data impact, migration/rollback, alternatives and explicit owner approval before execution.
