# 03.3 — Decision Log & Changelog

Keep product decisions separate from implementation history.

Decision records need ID/date, context, options, decision/rationale, consequences, affected specs, status and owner approval.

Changelog entries need date, version/build/commit, summary, affected files/features, user impact, tests/evidence, known issues and rollback notes. Do not treat workflow intentions as proof that a tool or board is configured.
