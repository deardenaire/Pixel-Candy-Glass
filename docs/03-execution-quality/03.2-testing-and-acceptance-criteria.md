# 03.2 — Testing & Acceptance Criteria

## Principle
Test observable user outcomes, not only whether the project compiles or a screen renders.

## Test layers
Unit tests for domain rules; integration tests for persistence/event delivery; component tests for controls; end-to-end journeys; visual checks at agreed mobile sizes; manual touch/keyboard/interruption tests; performance checks; regression tests for existing features.

## Test dimensions
Normal path; first-use/empty; invalid input; loading/slow response; offline; save failure/retry; repeated actions; duplicate events; back navigation; refresh/restart; small/large screens; reduced motion; accessibility labels/focus.

## Visual acceptance
Hierarchy/spacing; consistent material/light/typography; pixel-art crispness/scale; no clipping/safe-area collision; readable contrast; correct feedback; designed empty/error states; no placeholders where approved art exists.

## Evidence
Record test ID, expected/actual result, device/viewport, pass/fail, screenshot/recording/log, commit/build ID, tester and date.

Before verification rerun affected and relevant regression tests, inspect build/console errors, verify persistence after reload, inspect migration effects and record limitations. A screenshot alone does not prove feature completion.
